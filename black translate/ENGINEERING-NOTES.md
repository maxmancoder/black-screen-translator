# OCR and translation reliability notes

The MV3 service worker dispatches translations and manages the persistent cache. The content script scans and renders text and image overlays. OCR runs in an offscreen document using the bundled Tesseract.js worker/core. The English model is bundled; other languages still use the configured remote model repositories. Existing `auto` OCR settings continue to derive a language from the translation source; new installations default to `eng`. Translation source language remains independent.

Google's free `translateHtml` and `translate_a/t` endpoints are undocumented and may change or stop working. Their embedded public client key is not a secret. The existing Google Cloud provider is a separate configurable option; migrating to it would require users to supply their own credentials and is not part of this change. The free service sends selected page/OCR text to Google; other configured providers receive that text instead. Broad host permissions and all-frame injection enable translation across sites but expose the extension to sensitive page content. API credentials entered for other providers are held in Chrome extension storage, not a secure vault. Use only on pages and providers you trust. Diagnostics should not print page text or image URLs.

Translation results have per-item `statuses`: `success`, `failed`, or `pending` while work is in progress. Failed entries retain the original as a display fallback and are not cached as successes. Persistent cache keys use version v3 and a SHA-256 fingerprint of effective provider settings, including credentials and custom headers; plaintext credentials/headers are not stored in the key. Changing a credential, model, URL, header, or relevant translation parameter selects a separate cache namespace. Old buckets remain until normal eviction or cache clearing. The page-local cache is cleared on relevant configuration changes, including `llmMaxTokens`.

Only exactly uniform images are skipped as blank. This avoids guessing that low-contrast or sparse images are textless, at the cost of more OCR. Cropped and data URL images bypass the OCR cache to avoid collisions. The current size cap, PSM selection and geometric grouping remain heuristic; long images, multicolumn text, rotated/perspective text, and comics need further measured evaluation. No tiling or automatic deskew was added. Remote model loading, worker creation and each OCR pass can fail; failures are reported rather than counted as recognized text.

## Verification

Run `node tools/selftest.js`, `node tools/regression.js`, `node tools/domsmoke.js`, `node tools/imgsmoke.js`, and `node tools/ocrsmoke.js`. These use mocks; they do not measure real OCR accuracy or make Google requests.

Manual Chrome verification (requires network for Google): load this directory unpacked at `chrome://extensions`, open a non-sensitive test page, open the extension and run its OCR self-test; check that English text is recognized. Translate a page and an image, then change provider and target language and repeat. Test a low-contrast image and a CSS background image; simulate offline mode and verify errors are shown rather than cached as translations. Re-enable network and retry. Inspect the extension service worker, offscreen document and page consoles for errors. Do not use sensitive page content in these checks.

A real-image Tesseract.js corpus and browser automation are still needed to measure recognition, reading order, memory and latency on screenshots, columns, comics, photographs, rotation and blank images. A separate opt-in Google integration test is also needed; do not make routine tests depend on Google's availability.
